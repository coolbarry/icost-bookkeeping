# config/ 填写说明

**这个目录里的 4 个文件必须换成你自己的，否则系统跑出来的分类和账户全是错的。**

按下面的顺序填：

| 顺序 | 文件 | 来源 | 注意 |
|:--:|---|---|---|
| 1 | `categories.json` | App「设置 → 分类管理」**逐页截图** | ⚠️ **不能从历史数据反推**——历史只反映"用过的"，反映不了"配过的"（0 笔记录的分类查不到） |
| 2 | `accounts.json` | App「设置 → 账户管理」截图 | 账户名必须和 App 里**完全一致**，否则导入后对不上 |
| 3 | `pay_mapping.json` | 你账单里「支付方式」字段的实际值 | 把 `规则` 里的 `账户` 改成你自己的账户名 |
| 4 | `merchant_map.json` | 可留空 | 用久了把归类错的商家加进来，命中率会越来越高 |

---

## categories.json · 四层结构

```
账本 › 收支方向 › 一级分类 › 二级分类
```

每个账本的分类是**完全独立**的。示例：

```json
{
  "日常": {
    "支出": { "餐饮": ["三餐", "外卖"], "交通": ["公交地铁", "打车"] },
    "收入": { "工资": ["月薪", "奖金"] }
  }
}
```

账本名要和 App 里的**一模一样**（包括「日常/收入」这种带斜杠的）。

## accounts.json · 分组结构

```json
{
  "日常消费账户": {
    "note": "分组说明，随便写",
    "accounts": [
      {"name": "「消费」微信", "type": "微信钱包", "bal": 0, "hist": 0, "main": true}
    ]
  }
}
```

- `name` —— **最重要**，必须和 App 里完全一致
- `bal` —— 余额，只用于展示，不影响导入
- `hist` —— 历史出现次数，可留 0
- `main` —— 是否为主要账户，建议都填 true

> ⚠️ 这个文件里**只能有分组，不能有 `_说明` 之类的额外键**，引擎会遍历所有值。

## pay_mapping.json

`规则` 从上到下匹配，命中即停，所以**具体的要放在通用的前面**。

```json
{"匹配": ["零钱"], "账户": "「消费」微信", "优先级": 1, "说明": "微信零钱"}
```

`组合支付处理` 里的 `非账户关键词`（红包/立减/券）会在「A&B&立减」这种组合支付里被跳过。

## merchant_map.json

```json
"商家名": ["账本", "方向", "一级分类", "二级分类"]
```

用于品牌名这种不含品类词的场景（比如「海底捞」看不出是餐饮）。
用得越久条目越多，需要人工确认的笔数就越少。

## rules.json

语义规则，`匹配` 是正则，多个词用 `|` 分隔。分类名必须存在于 `categories.json`。
一般不用改，除非你的分类树和示例差别很大。

## import_fix.json

每轮记账的人工修正表，可以每轮清空后重填：

- `patch` —— 按 `日期|金额` 精确定位一行，改它的字段
- `drop` —— 按 `日期|金额` 直接剔除（用于去重）
- `cat_map` —— 已归档分类的重映射（比如「购物」已归档 → 映射到「其他支出」）
- `_导入选项.冲减类型可导入` —— 默认 `false`，即退款/报销不进导入文件，改走手工补录

# 02 · iCost 导入规范

> 想看"为什么踩这些坑"的完整过程，见 [03_踩坑记录.md](03_踩坑记录.md)。

## 一、导入模板的权威定义

来源：App 内「导入账单 → 下载模板」得到的 `icost_template.xlsx`。
**本项目已把这份官方模板存进 `config/icost_template.xlsx`**，系统直接用它当骨架，不再依赖外部文件。

- **sheet 名**：`icost_template`
- **列数**：10 列，顺序固定

| # | 列名 | 要求 |
|---:|---|---|
| 1 | 日期 | `2011年01月11日 12:00:00`（中文年月日） |
| 2 | 类型 | `支出` / `收入` / `转账`（还款等由 App 内部类型承担） |
| 3 | 金额 | **正数**，正负由「类型」决定，不靠符号 |
| 4 | 一级分类 | 必须存在于**当前账本**的分类树中 |
| 5 | 二级分类 | 必须挂在对应一级分类下；没有就留空 |
| 6 | 账户1 | 支出=付款账户 / 收入=收款账户 / 转账=转出方 |
| 7 | 账户2 | 仅转账、还款需要，填转入方 / 被还账户 |
| 8 | 备注 | 自由文本 |
| 9 | 货币 | `CNY` |
| 10 | 标签 | `#标签1#标签2` |

示例行：

```
2011年01月11日 12:00:00 | 支出 | 40   | 餐饮 | 三餐 | 支付宝 |      | 吃饭（早餐）     | CNY | #标签1
2011年01月11日 12:00:00 | 收入 | 1000 | 工资 |      | 工资卡 |      | 工资入账         | CNY | #标签2
2011年01月11日 12:00:00 | 转账 | 1000 | 其他 |      | 工资卡 | 储蓄卡 | 工资转入储蓄卡   | CNY | #标签1#标签2
```

## 二、导出格式 ≠ 导入格式

iCost 的导出文件是 **21 列**，多了 `账本 / 位置 / 退款 / 优惠 / 手续费 / 图片链接1-3 / 图片附件1-3`，
而且文件名写着「（仅供查看，不用于数据恢复）」。

**千万别把导出文件改改就拿去导入。** 差异对照：

| 项 | 导出 | 导入模板 |
|---|---|---|
| 列数 | 21 | 10 |
| sheet | 收支账单 | icost_template |
| 日期 | `2024/05/12 14:44:00` | `2024年05月12日 14:44:00` |
| 支出金额 | `-148.0` | `148` |
| 账本 | 有列 | 无列（导入时在 App 里选） |

## 三、必须按账本拆文件

iCost 的导入入口在**某个账本内部**：先切到账本，再导入。
所以一个文件里只能有同一账本的记录，否则分类匹配会全部失败
（每个账本的一级/二级分类完全独立，只有 转账/还款/其他支出 跨账本共用）。

`split.sh` 会按账本拆成：

```
NN_iCost导入_<账本>.xlsx   ← 主用
NN_iCost导入_<账本>.csv    ← 备用（UTF-8 BOM，xlsx 失败时改试）
导入校验报告.md
```

## 三·补、xlsx 内部 XML 也得跟官方一致（最容易忽略）

只有 10 列表头还不够。**openpyxl 造出来的 xlsx 在 XML 层面和官方模板不一样**，
iOS 端的解析器很挑食：

| 内部细节 | 官方模板 | openpyxl 默认 | 处理 |
|---|---|---|---|
| 共享字符串 | `<si><t>日期</t></si>` | `<si><r><t>日期</t></r></si>` 富文本 run | 必须自己拼 |
| 单元格类型 | `t="s"` + 索引 | 有时退化成 `t="inlineStr"` | 必须 `t="s"` |
| 中文 | 真 UTF-8 汉字 | 有时写成 `&#26085;` 数字实体 | 必须真汉字 |
| dimension | `A1:J4` | `J4`（缺起点） | 必须带起点 |
| 金额 | `40` | `40.0` | 整数去小数点 |

**解决方案**：`export_split.py` 的 `write_xlsx_like_official()` 直接把
`config/icost_template.xlsx`（App 原版模板）当骨架，只替换
`xl/worksheets/sheet1.xml` 和 `xl/sharedStrings.xml`，其余 part 原样保留。
这样产出的文件和 App 自带模板在结构上完全一致。

→ **不要再用 openpyxl 的 `Workbook.save()` 生成导入文件。**

## 三·补、退款与报销怎么做「关联」

### iCost 的内部机制（从 3,582 笔历史实测得出）

| 类型 | 作用 | 历史笔数 |
|---|---|---|
| 待报销 | 支出标记「这笔钱以后有人给我报」 | 12 |
| 已报销 | 报销款到账后，原支出记录**改状态**（不新建记录） | 9 |
| 报销入账 | 配套生成的收入 | 9 |
| 退款入账 | 带**原订单分类**做冲减 | 66 |

`已报销` 与 `报销入账` 的 9 笔金额 **100% 一一对应**
（28.13 / 36.3 / 40 / 44.03 / 49.62 / 70 / 100 / 103.16 / 490），分类也一致。
→ 关联靠「**类型 + 金额 + 分类**」配对，**不是 ID**。

### 三条铁律

1. **类型是冲减不是收入**。记成「收入」会虚增收入、虚增储蓄率低估
2. **分类必须沿用原订单的分类**。历史 66 笔退款入账没有一笔落在「其他」上，
   全是 交通出行/火车飞机、购物/服饰、住房支出/房租 这类原订单分类
3. **账本必须和原订单一致**。跨账本冲不掉（比如健身房充值在成长提升，
   退款却记在日常/收入 → 完全对冲不上）

### 导入层面做不到硬链接

10 列模板没有「关联 ID」，也没有导出格式里的「退款」列。
所以只能在**备注**里写明原订单（日期 / 商户 / 金额），供日后人工反查。
`config/import_fix.json` 里用 `类型` + `账本` + `一级分类` + `二级分类` + `备注` 组合实现。

### ⚠️ 已实测：导入不认「退款入账 / 报销入账」（2026-10-17）

官方模板的示例行只有 `支出 / 收入 / 转账` 三种，导入解析器**只认这三种**。
`退款入账` / `报销入账` / `待报销` / `已报销` 写了会解析失败。

**处理办法：冲减类不进导入文件，改走 App 内手工补录。**

`export_split.py` 默认把它们从按账本拆分的 xlsx 里剔除，并额外产出
`手工补录清单.md`（含每笔的账本/类型/金额/分类/账户/备注 + 具体点击路径）。

开关在 `config/import_fix.json`：

```json
"_导入选项": { "冲减类型可导入": false }
```

设为 `true` 可恢复「写进导入文件」的旧行为（将来 iCost 支持了再改）。

> 不能退而求其次导成「收入」：那会虚增收入、又冲不回支出，
> 储蓄率和分类口径双重失真，比不记还糟。

## 四、常见导入失败原因（按排查顺序）

1. **列数/表头/sheet 名不对** —— 用了 21 列导出格式 → 用 `split.sh` 重生成
2. **一个文件混了多个账本** —— 按账本拆
3. **日期格式** —— 必须是 `YYYY年MM月DD日 HH:MM:SS`
4. **金额带负号** —— 一律取绝对值
5. **一级分类不在当前账本的分类树里** —— 比如「购物」已归档（历史 268 笔还在用，
   但 App 里已归档，导入匹配不到）→ 在 `config/import_fix.json` 的 `cat_map` 里重映射
6. **转账/还款缺账户2** —— 转出转入必须成对，缺一个就会失败或产生脏数据
7. **收入行缺账户1** —— AA 收款、报销、退款这类容易漏，必须补
8. **空单元格写成 `None`** —— 一律写空字符串

## 五、人工修正表：`config/import_fix.json`

```jsonc
{
  "cat_map": { "购物": { "to": "其他支出", "c2": "", "原因": "已归档" } },
  "patch": [ { "key": "2026/09/22 01:39:50|403",
               "set": { "账户2": "「临时」余额宝「攒着」" },
               "原因": "转账必须补双方账户" } ],
  "drop":  [ { "key": "2026/10/05 11:58:06|10.14", "原因": "重复记录" } ]
}
```

- `key` 格式：`原日期|金额`（日期用源文件里的写法，如 `2026/09/22 01:39:50`）
- `patch.set` 里可写 `账户1` / `账户2` / `一级分类` / `二级分类` / `备注` 等任意列

## 六、导入操作流程

1. 打开 iCost，切到 **日常/收入** 账本
2. 进入导入，选 `01_iCost导入_日常-收入.xlsx`
3. 确认预览无误后导入
4. 切到 **情感社交**，导入 `02_iCost导入_情感社交.xlsx`
5. 依次类推；**一次只导一个文件**
6. 导完随便抽查 3-5 笔（尤其大额和转账）

若 xlsx 一直失败，改用同名 csv（UTF-8 BOM 编码，Excel/iCost 都能认）。

# 给 AI 的指令 · iCost 记账流程

> 用途：把这份文件发给任何 AI（WorkBuddy / Codex / Claude 等），它就能独立完成
> 从账单到可导入文件的全过程。**用户只需做 3 件 AI 做不到的事**（见文末）。
>
> 用户典型指令：「帮我记账，账单在 `账单/` 里，按 `给AI的指令.md` 走。」

---

## 0. 开始前：先读这些（5 分钟，能省 2 小时）

### 0.0 先确认系统配置好了没有

```bash
cd "$ROOT/icost-system" && ./check.sh
```

| 结果 | 你怎么接 |
|---|---|
| 🟡 退出码 2（未配置） | **停下来**。先走 [`初次引导.md`](初次引导.md)：问用户 6 个问题、收 3 样材料、写配置、再自检。**不要拿空配置跑引擎。** |
| 🔴 退出码 1（有问题） | 按列出的错误修完再继续 |
| 🟢 退出码 0（就绪） | 继续往下 |

顺便读一眼输出的统计（账本数 / 一级分类数 / 账户数），后面归类时要用。

### 0.1 然后按顺序读完，不要跳过：

| 必读 | 内容 | 为什么 |
|---|---|---|
| `docs/03_踩坑记录.md` | 三个真实的坑 | **最重要**。不读几乎一定会重蹈覆辙 |
| `docs/02_导入规范.md` | 导入文件的 10 列逐列要求 | 生成文件时对照 |
| `config/categories.json` | 四层分类树（账本›方向›一级›二级） | 分类只能从这里取，不能自己编 |
| `config/accounts.json` | 账户体系 | 账户只能从这里取 |
| `config/import_fix.json` | 人工修正表 + 导入开关 | 已有的修正别重复造 |

约定：
- `$ROOT` = 项目根目录（`icost-system/` 的上一级）
- 原始账单在 `$ROOT/账单/`，中间产物在 `$ROOT/output/`，导入文件在 `$ROOT/导入文件/`
- 所有脚本自带 Python 探测，**不要** 再手动指定 `PYTHON=`

## 1. 跑引擎

```bash
cd "$ROOT/icost-system"
./run.sh ../账单/<微信账单.xlsx> ../账单/<支付宝账单.csv> ../账单/<iCost历史.xlsx>
```

参数只有微信是必填；支付宝和历史没有就不传（但**历史强烈建议传**，否则会重复导入）。

**检查点**：终端应打印类似

```
总笔数 91 | 支出 xx 笔 | 收入 xx 笔
自动完成 69 笔 (91%) | 需人工确认 7 笔
```

产出在 `$ROOT/output/`：`记账确认.html`、`记账明细.csv`、`iCost明细_中间文件.xlsx`、
`已剔除-重复记录.csv`。

| 异常 | 处理 |
|---|---|
| `ModuleNotFoundError: openpyxl` | `pip install openpyxl` 后重跑 |
| `未找到表头` | 账单格式变了。用 Excel 打开看第一行，改 `core/engine.py` 的 `_parse_xlsx` / `_parse_csv` 列索引 |
| 自动完成率 < 60% | 大概率是 `merchant_map.json` 没命中。抽查归类错的商家，补进配置再重跑 |

**然后告诉用户**：打开 `$ROOT/output/记账确认.html`，处理标「待确认」的几笔，
点「复制全部」，把结果发回。

> ⚠️ 不要让用户直接导入 `output/` 里的任何文件——那是未确认的草稿。

## 2. 等用户确认

用户会发回一段确认结果。**不要自己替用户猜**——「这笔是什么」只有用户知道。

如果用户长时间没回复，把待确认的几笔**单独列出来**（日期 / 金额 / 商户）提醒一次，
别一股脑重发整个页面。

## 3. 生成 `已确认明细.xlsx`

把确认结果落成 **21 列**的中间文件（iCost 导出格式），写到 `$ROOT/已确认明细.xlsx`。

表头（顺序固定）：

```
日期 | 类型 | 金额 | 一级分类 | 二级分类 | 账户1 | 账户2 | 备注 | 货币 | 标签 |
账本 | 位置 | 退款 | 优惠 | 手续费 | 图片链接1 | 图片链接2 | 图片链接3 |
图片附件1 | 图片附件2 | 图片附件3
```

规则：

- 日期 `YYYY/MM/DD HH:MM:SS`（斜杠，中间文件用这个；`split.sh` 会转成中文格式）
- **金额：支出为负、收入为正**（这是导出格式的要求）
- 分类必须存在于 `config/categories.json` 的 `账本 → 方向 → 一级 → 二级` 路径上
- 二级分类可以为空

**这一步你必须主动做对（用户最容易漏的 4 件事）**：

1. **退款 / 报销是冲减，不是收入。** 类型用 `退款入账` / `报销入账`。
   记成「收入」会让本月收入虚增，储蓄率双重失真。
2. **冲减的分类沿用原订单**，不要塞进「其他」。
3. **冲减的账本必须和原订单一致**（跨账本冲不掉，等于白记）。
   例：原订单 2000 健身充值在「成长提升」，退款也必须放「成长提升」。
4. **转账 / 还款必须有账户1 + 账户2 两个**；**收入行也必须有账户1**。

> 参考样例：`example/已确认明细_样例.xlsx`

## 4. 生成导入文件

```bash
cd "$ROOT/icost-system"
./split.sh ../已确认明细.xlsx ../导入文件
```

脚本会：按账本拆分 → 对齐官方模板 XML → 逐字段校验 → 产出报告和清单。

产出：

| 文件 | 用途 |
|---|---|
| `NN_iCost导入_<账本>.xlsx` | 主用，一次导一个 |
| `NN_iCost导入_<账本>.csv` | 备用（UTF-8 BOM） |
| `手工补录清单.md` | 退款/报销这些 iCost 导入不认的记录 |
| `导入校验报告.md` | 逐字段校验结果 |
| `00_诊断_官方原版模板.xlsx` | 官方模板原样，先试它 |
| `00_诊断_单笔探针.xlsx` | 1 笔真实记录 |

**检查点**：报告里的问题统计应为 0。不为 0 就按报告里的提示修。

### ⚠️ 绝对不能做的事

> **绝不用 `openpyxl.Workbook().save()` 直接产出导入文件。**
>
> openpyxl 生成的 xlsx 在 XML 层面和官方模板不一致（富文本 run、inlineStr、
> 数字实体、`40.0` 这种小数），iOS 解析器直接判「解析失败」。
> 必须走 `core/export_split.py` 的 `write_xlsx_like_official()`——它拿
> `config/icost_template.xlsx` 当骨架，只替换 `sheet1.xml` + `sharedStrings.xml`。

### 导入文件长什么样（10 列）

```
日期 | 类型 | 金额 | 一级分类 | 二级分类 | 账户1 | 账户2 | 备注 | 货币 | 标签
```

- sheet 名必须叫 `icost_template`
- 日期 `2026年09月28日 11:41:04`（中文格式）
- **金额全是正数**（收入支出都一样）
- **没有账本列**——账本在 App 里切
- 空值写空字符串，不要写 `None`

## 5. 交还给用户

告诉用户：

1. 先试 `00_诊断_官方原版模板.xlsx` —— **连它都失败说明问题在导入方式**
   （要走 iOS「文件」App 分享进 iCost），改文件没用
2. 再试 `00_诊断_单笔探针.xlsx`，然后才是 01 / 02 / 03
3. **切到账本再导入**，一次一个文件
4. 退款 / 报销照 `手工补录清单.md` 手工建——**iCost 导入不认这两个类型**，
   官方模板的示例行只有 `支出 / 收入 / 转账`

---

## 6. 收尾

用户导入完，问一句有没有归类错的。有的话：

```json
// config/merchant_map.json
"海底捞": ["日常/收入", "支出", "日常餐饮", "日常三餐"]
```

格式：`"商户名": [账本, 方向, 一级分类, 二级分类]`
（从 `记账明细.csv` 的「交易对方」列取商户名，值必须存在于分类树。）

用得越久命中率越高，需要人工的笔数会越来越少。

---

## 三条红线

1. **导出格式 ≠ 导入格式。** 导出 21 列（文件名写着"仅供查看，不用于数据恢复"），
   导入只有 10 列。中间文件不能直接导。
2. **一个文件一个账本**，导入文件里没有账本列。
3. **导入只认 `支出 / 收入 / 转账`。** 冲减类走手工补录。

---

## 只有用户能做的 3 件事（别替他猜）

| 事 | 为什么 |
|---|---|
| 从微信 / 支付宝 / iCost 导出账单 | 要密码 / 人脸识别 |
| 回答「这笔是什么」 | 只有用户知道当时发生了什么 |
| 在 iCost 里点导入、点手工补录 | 在手机上 |

遇到这三件事，**停下来问用户**，不要自己编。

---

## 排查心法（卡住时按这个顺序）

1. **找权威基准** —— 官方模板 `config/icost_template.xlsx` 就是基准，和它比
2. **先证明基准能用** —— 连官方原版都失败，问题就不在文件
3. **二分法** —— 从 1 笔开始，逐步加字段，定位到具体哪一列出问题
4. **"解析失败" 是结构问题，不是数据问题** —— 优先查 XML 写法和列数，别纠结内容

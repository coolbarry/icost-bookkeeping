# 初次引导 · 从零到第一笔账

> **这份文件是给 AI 的。** 用户不需要看手册，只要回答几个问题、给几样材料。
>
> 用户的一句话指令通常长这样：
> ```
> 我第一次用这套系统，帮我配置好。系统在 <路径>/icost-system
> 请按 icost-system/初次引导.md 引导我。
> ```
>
> **你的角色**：先问清楚、再给建议、最后才动手写配置。
> 不要一上来就跑脚本 —— 配置是空的，跑出来全是错的。

---

## 总览：初次使用走 5 步

```
[AI ]  0  体检 ───── ./check.sh ────→ 🟢就绪？直接走 给AI的指令.md
                                      🟡未配置？继续往下
[你 ]  1  回答 6 个问题（都有默认值，回「默认」就行）
[你 ]  2  给 3 样材料（分类截图 · 账户截图 · 历史导出）
[AI ]  3  出「诊断与建议」── 只给建议，不改用户 App 里的设置
[AI ]  4  写配置 ───── ./check.sh 自检 ────→ 不通过就改到通过
[AI ]  5  试跑：先 1 个月 → 3 笔探针 → 全量
```

**时间**：用户约 15 分钟（大部分是截图），AI 侧约 10 分钟。

---

## 第 0 步 · AI 先体检（2 分钟）

```bash
cd <路径>/icost-system && ./check.sh
```

| 退出码 | 含义 | 你怎么接 |
|---|---|---|
| 🟢 0 | 已配置，可以直接用 | 不用走引导，直接跳到 `给AI的指令.md` |
| 🔴 1 | 已配置但有错 | 按列出的错误逐条修，修完再跑一次 |
| 🟡 2 | **未配置（模板状态）** | 走下面的流程 |

> 脱敏包里 `config/SETUP_PENDING.md` 就是「未配置」标记。
> 配置写完后**删掉这个文件**，再跑一次 `./check.sh` 确认变绿。

---

## 第 1 步 · AI 问用户 6 个问题

**分批问，一次 2～3 个。** 每个问题都给默认值，用户可以只回「默认」。
提问时**原样带上选项字母和默认值**，别改写成开放问题 —— 用户回得越快，成功率越高。

### 批次 1 · 你的习惯（先问这个）

> **Q1 你多久记一次账？**
> A 每周　B 每月（默认）　C 想起来才记
> *影响：C 的话我会额外提醒你「超过 45 天的账单就不建议补了，失忆账单猜不准」*

> **Q2 记账主要为了什么？（可多选）**
> A 控制支出　B 看清净资产　C 报销/对账　D 单纯记录（默认 A+B）

> **Q3 有没有需要单独一本账的事？**
> 比如生意、装修、旅行、养娃。没有就回「没有」（默认）。
> *影响：有的话我会建议你在 iCost 里新建一个账本，并在分类树里加进去*

### 批次 2 · 技术选择（有默认值，可以直接过）

> **Q4 转账要不要记？**（账户互转、还花呗、余额宝转入转出）
> A 记（默认）　B 不记
> *A 的理由：不记的话账户余额永远对不上，净资产是假的*

> **Q5 扣款渠道要不要区分到具体卡？**
> A 按账单里的「支付方式」自动识别（默认）　B 统一记成微信/支付宝
> *A 的理由：微信/支付宝账单里本来就写了扣的是哪张卡，不用你人工核对*

> **Q6 小额支出怎么处理？**（≤50 元的那种）
> A 逐笔记　B 只记一个月度总额（推荐）
> *推荐 B：这类笔数通常占 75%，金额却只占 8%，逐笔记的性价比极低*

### 批次 3 · 按需追问（前面的回答触发时才问）

- Q1 选了「报销/对账」→ 追问：一个月大概几笔报销？**这决定要不要重点讲「待报销 → 已报销」的用法**
- Q3 有单独账本 → 追问：账本叫什么名字？我把它加进分类树
- Q6 选了 A → 不用追问，尊重用户选择

**全部问完后，用一段话复述你的理解让用户确认**，再进入第 2 步。别跳过复述。

## 第 2 步 · 用户准备 3 样材料

把这张表原样发给用户，**说清楚每样是干什么用的** —— 用户知道为什么，配合度会高很多。

| # | 材料 | 怎么拿 | 不给会怎样 |
|---|---|---|---|
| 1 | **分类管理截图** | iCost → 设置 → 分类管理 → 每个账本都切一遍，**支出和收入各截一张** | 分类只能瞎猜，归类全错 |
| 2 | **账户管理截图** | iCost → 设置 → 账户管理 → 截全（要能看到完整账户名） | 账户名对不上，导入后账户全乱 |
| 3 | **历史账单导出** | iCost → 设置 → 账单导出 → 得到 xlsx | ① 学不到你的消费习惯，自动归类率会掉一半 ② **会重复导入已有的账** |

截图要求提醒用户：

- 分类列表要**滚到底截完整**，别只截上半屏
- 一级分类要**展开**，能看到下面的二级
- 账户名长的别被截断（iCost 里账户名可能有括号、尾号）

> 💡 第 3 份（历史导出）最关键 —— 引擎会从里面**自动学习**你过去的归类习惯。
> 有了它，第一次的自动归类率就能到 70%+；没有它，只能靠通用规则，会低很多。

**可选**：最近 1 个月的微信 + 支付宝账单（用于第 5 步试跑）。没有也可以等下一轮。

## 第 3 步 · AI 出「诊断与建议」

拿到材料后，你做的事分两半：**先读数据，再给建议**。

### 3.1 先把配置写出来（不然没法分析）

按第 4 步的格式，从截图生成 `categories.json` 和 `accounts.json`。
即使后面用户要改分类，也得先有这份基线。

### 3.2 分析历史导出，给出 4 项诊断

用脚本读历史 xlsx（21 列，sheet 名 `收支账单`），算这些指标：

| 诊断项 | 看什么 | 常见结论 |
|---|---|---|
| **金额分布** | 中位数 vs 均值、≤50 元占多少笔/多少钱 | 典型：≤50 元占 75% 笔数但只占 8% 金额 → 建议分级记账 |
| **分类健康度** | 「其他」类占比、一级分类数量 | 「其他」>10% 说明分类体系有黑洞 |
| **账户分布** | 每个账户的笔数、日常可用资金占比 | 日常账户常常只是过账账户，不是钱袋子 |
| **借贷/转账流量** | 转账还款笔数、信用卡/花呗 | 决定 pay_mapping 要覆盖哪些渠道 |

诊断基于真实数据，不要空谈。参考 `docs/05_复盘方法论.md` 里的口径。

### 3.3 给建议（3～5 条，明确标出「要改 / 不用改」）

**⚠️ 红线：你只能建议，不能直接改用户 iCost 里的任何设置。**
用户在手机上改，你改不了；而且分类一旦改，历史数据的口径就变了。

建议的写法（要具体到「改哪个、改成什么」）：

```
建议 1（推荐做）：「其他支出」这个月有 42 笔、占 11%，建议拆成
                 「日用杂项」和「临时垫付」两个二级分类。
建议 2（可做可不做）：「数码配件」这个一级分类只有 3 笔，
                    可以并入「生活住宿」减少维护成本。
建议 3（建议做）：9/16 有一笔 -441 记在「商户消费」，看备注是火车票，
                应该在 App 里改成「交通出行/火车飞机」。
```

## 第 4 步 · AI 写配置

### 最小可用原则

**第一次只需要 3 个文件**：`categories.json` + `accounts.json` + `pay_mapping.json`。

`rules.json` 保留包里的通用版就行，`merchant_map.json` **可以是空的** ——
引擎的历史学习层会从你给的历史导出里自己学关键词，用得越久越准。

### 4.1 categories.json（四层分类树）

```json
{
  "日常/收入": {
    "支出": {
      "日常餐饮": ["日常三餐", "饮料酒水", "外卖"],
      "交通出行": ["公交地铁", "网约出租", "火车飞机"]
    },
    "收入": {
      "工资": ["月薪", "奖金"],
      "其他收入": []
    }
  }
}
```

结构：`{账本: {方向: {一级: [二级]}}}`

**AI 易错点（必看）**：

1. **方向只有「支出」和「收入」两种**，别写「转账」
2. 「转账」「还款」「退款入账」「报销入账」是 iCost **系统自带**的，
   不在分类管理里，**不要**写进分类树
3. 分类名必须和截图**一字不差**，包括空格和连字符
   （例：`父母-医疗` 里的 `-` 是合法字符，别改成 `/`）
4. 没有二级分类就写空数组 `[]`，别省略这个一级
5. 账本名要和 App 里的完全一致（用户 Q3 新建的账本也要加进来）

### 4.2 accounts.json（账户体系）

```json
{
  "日常消费账户": {
    "note": "平时花钱走的账户",
    "accounts": [
      { "name": "「消费」微信", "type": "微信钱包", "bal": 0, "hist": 0, "main": true },
      { "name": "「消费」招行储蓄卡", "type": "储蓄卡", "bal": 0, "hist": 0, "main": true }
    ]
  }
}
```

**AI 易错点**：

1. **顶层不能有 `_说明` 之类的下划线键** —— 引擎会遍历 value 调 `.get('accounts')`，
   字符串没有这个方法，直接崩。说明要写到 `config/README.md`
2. `name` 必须和 App 里**完全一致**（导入时靠名字匹配）
3. `bal`（余额）和 `hist`（历史笔数）第一次都填 0，不影响导入，只是展示用
4. 账户名建议用「角色」前缀，如 `「消费」`、`「应急」`、`「投资」`，一眼看出用途

### 4.3 pay_mapping.json（支付渠道 → 账户）

```json
{
  "规则": [
    { "匹配": ["零钱通", "零钱"], "账户": "「消费」微信", "优先级": 1 },
    { "匹配": ["招商银行", "招行"], "账户": "「消费」招行储蓄卡", "优先级": 2 },
    { "匹配": ["花呗"], "账户": "「消费」花呗", "优先级": 3 }
  ],
  "组合支付处理": { "_非账户关键词": ["立减", "红包", "优惠券", "积分"] },
  "卡号尾号识别": { "已知": {} }
}
```

**怎么拿到「匹配」的取值**：从历史导出的「账户1」列，以及微信账单的「支付方式」、
支付宝账单的「收/付款方式」列，把所有出现过的取值去重列出来，逐个映射。
**不要凭空想** —— 微信可能写「零钱」，也可能写「招商银行(0002)」。

组合支付（如 `招行(0002)&立减`）会按 `&` 拆开，跳过「立减/红包/券」，取第一个真实账户。

### 4.4 写完必须自检

```bash
./check.sh
```

**不通过就改到通过**，别带着错误配置往下跑。脚本会告诉你具体哪条规则的分类不在分类树里。

通过后删除 `config/SETUP_PENDING.md`。

## 第 5 步 · 试跑（小步验证，别一次全量）

### 5.1 先跑 1 个月

```bash
./run.sh <微信账单.xlsx> <支付宝账单.csv> <iCost历史.xlsx>
```

看终端输出的**自动完成率**：

| 完成率 | 判断 | 动作 |
|---|---|---|
| ≥ 85% | 配置很好 | 继续 |
| 60～85% | 正常（第一次常这样） | 继续，把归类错的商家补进 `merchant_map.json` |
| < 60% | 配置有问题 | 检查 `categories.json` 是否漏了账本；历史导出是否传了 |

### 5.2 用户在确认页核对

打开 `output/记账确认.html`，处理标「待确认」的几笔。

**提醒用户**：备注里写清「谁的 + 什么性质」（例：帮同事垫的、给孩子买的）。
AI 能猜对商家，但猜不出这笔钱的关系。

### 5.3 生成导入文件后，先做 3 笔探针

```bash
./split.sh <已确认明细.xlsx> ../导入文件
```

**让用户先导入 `00_诊断_官方原版模板.xlsx`** —— 连官方原版都失败，
说明问题在导入方式（要走 iOS「文件」App 分享进 iCost），改文件没用。

探针成功，再按账本逐个导入 01 / 02 / 03。

### 5.4 全量

第一次建议只跑 **1 个月**。确认没问题，下次再补历史区间。
一次补半年，会出现大量「这笔是什么」的失忆账单，谁也救不了。

## 第 6 步 · 固化（下次不用再走引导）

把这次的结论写下来，避免下次重复问：

1. 用户的记账习惯、账本划分 → 写进项目记忆或 `config/README.md`
2. 归类错的商家 → 补进 `config/merchant_map.json`（格式：`"商户名": [账本, 方向, 一级, 二级]`）
3. 反复出现的特例 → 写进 `config/import_fix.json`

**之后每次记账，用户直接说**：

```
帮我记账，按 icost-system/给AI的指令.md 走。
```

不用再走这份引导。

## 附 A · 快速通道（用户不想被问）

如果用户说「别问了，直接弄」，跳过第 1 步，全部用默认值：

- Q1 每月　Q2 控制支出+看清净资产　Q3 没有
- Q4 记转账　Q5 自动识别扣款渠道　Q6 逐笔记（保守，避免用户对不上账）

然后直接要材料。**但 Q6 不要用「合并总额」默认值** —— 那是优化项，
等用户熟悉了再提。

## 附 B · AI 在这 5 步里的红线

1. **不要替用户回答「这笔是什么」**。只有用户知道当时发生了什么。
2. **不要改用户 iCost 里的设置**。你只能建议。
3. **不要跳过 `./check.sh`**。带着错误配置跑引擎，浪费的是用户的时间。
4. **不要用 `openpyxl.Workbook().save()` 生成导入文件**。
   必须走 `split.sh`（它克隆官方模板的内部 XML）。详见 `docs/03_踩坑记录.md`。
5. **不要让用户在确认前导入 `output/` 里的任何文件**。那是草稿。
6. **不要一次补超过 2 个月的账**。失忆账单归类必错。

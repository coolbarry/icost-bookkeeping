# 01 · 工作流 SOP

每次记账照这个顺序走一遍。**第 1 步不能省**，省了会重复导入。

> **第一次用？** 先走 [`../初次引导.md`](../初次引导.md) 完成配置（问问题 → 收材料 →
> 写 config → `./check.sh` 变绿），再回到本 SOP。
> 配置没填就跑引擎，归类会全错。

```
⓪ 首次配置（只做一次）：初次引导.md → check.sh 变绿
      ↓
① 导出三份文件
      ↓
② run.sh 跑引擎（自动归类 + 去重）
      ↓
③ 打开确认页，只处理「需确认」的几笔
      ↓
④ AI 生成「已确认明细.xlsx」
      ↓
⑤ split.sh 生成按账本拆分的导入文件
      ↓
⑥ 导入 iCost（先诊断文件，再正式文件）
      ↓
⑦ 按「手工补录清单」补退款/报销
      ↓
⑧ 抽查 3-5 笔，把归类错的商家加进 merchant_map
```

---

## ① 导出三份文件

| 文件 | 怎么导 | 用途 |
|---|---|---|
| **微信账单** | 微信 → 我 → 服务 → 钱包 → 账单 → 右上角 ⋯ → 下载账单 | 主数据源 |
| **支付宝账单** | 我的 → 账单 → 右上角 ⋯ → 开具交易流水证明 | 主数据源 |
| **iCost 历史** | iCost → 设置 → 账单导出 | **去重基准**，必须有 |

导出的 iCost 文件名通常长这样：
`（仅供查看，不用于数据恢复）iCost_YYYYMMDDHHMMSS.xlsx` —— 这名字本身就是提醒：**它是给人看的，不是给机器导回去的**。

建议命名后放到固定位置，比如项目根目录，方便下次直接传参。

---

## ② 跑引擎

```bash
cd icost-system
./run.sh <微信账单.xlsx> <支付宝账单.csv> <iCost历史导出.xlsx>
```

引擎做四件事：

1. **解析支付方式** → 自动映射账户（微信「支付方式」/ 支付宝「收付款方式」字段直接写明扣款来源）
2. **合并 AA 群收款**：同日 ≥3 笔、同额 ≤200 元、1 小时内 → 合成一笔
3. **与历史去重**：以「日期 + 金额绝对值」为键，剔除已入库的
4. **五层归类**：语义规则 → 商家映射 → 历史学习 → 品类词 → 平台兜底

终端会打印：

```
总笔数 91 | 支出 xx 笔 | 收入 xx 笔
自动完成 69 笔 (91%) | 需人工确认 7 笔
账本分布: {...}
```

产出在 `../output/`：`记账明细.csv`、`已剔除-重复记录.csv`、`记账确认.html`。

---

## ③ 确认页

打开 `../output/记账确认.html`。

- 页面**实时存 localStorage**，刷新/误关都不会丢
- 只需处理标记为「需确认」的项 —— 通常是转账、借出、礼金、AA
- 每笔有**补充说明框** + 20 个快捷标签。写清楚"这是谁的、什么性质"，
  比事后回忆准得多。例：
  - `某某结婚礼金，朋友己代付`
  - `健身房停业退款，原订单 9/28 充值 2000`
  - `同事甲合租房租分摊`
- 点「生成结果」→ 复制 → **整段发回给 AI**

---

## ④ 生成已确认明细

把复制的内容发给 AI，让它产出 `已确认明细.xlsx`（21 列导出格式的中间文件）。

这一步 AI 会顺便做几件你容易漏的事：

- 退款 / 报销的**账本跟着原订单走**（跨账本冲不掉）
- 分类**沿用原订单**的分类，而不是塞进「其他」
- 转账/还款补齐**账户2**
- 收入行补齐**账户1**

> 可以直接参照 `example/已确认明细_样例.xlsx` 看最终应该长什么样。

---

## ⑤ 按账本拆分

```bash
./split.sh <已确认明细.xlsx> ../导入文件
```

产出：

```
导入文件/
├── 00_诊断_官方原版模板.xlsx       ← 先导这个
├── 00_诊断_单笔探针.xlsx           ← 再导这个
├── 01_iCost导入_日常-收入.xlsx     ← 然后正式文件
├── 02_iCost导入_情感社交.xlsx
├── 03_iCost导入_成长提升.xlsx
├── 手工补录清单.md
└── 导入校验报告.md
```

**每次跑之前脚本会自动清掉上一轮的 `NN_iCost导入_*`，不会残留旧账本文件。**

---

## ⑥ 导入

顺序：**官方原版模板 → 单笔探针 → 01 / 02 / 03**。

| 试的文件 | 结果说明 |
|---|---|
| `00_诊断_官方原版模板.xlsx` | 一字未改的官方模板。**连它都失败 → 问题在导入方式**（要走「文件」App 分享进 iCost），改文件没用 |
| `00_诊断_单笔探针.xlsx` | 只有 1 笔真实记录。成功 → 格式对了；失败 → 某个字段值不兼容 |
| `01/02/03` | 正式数据 |

导入时注意：

- **先切到账本，再导入**。一个账本导完再切下一个
- xlsx 失败就换同名 `.csv`（UTF-8 BOM）
- iCost 支持「删除该次导入的所有账单」，导错了可以整批撤销

---

## ⑦ 手工补录退款 / 报销

iCost 导入不认 `退款入账` / `报销入账`，这几笔照 `手工补录清单.md` 手工建。

清单里每笔都给了：账本、类型、金额、分类、账户、备注，**以及具体的点击路径**。

最短路径是「**长按原订单那笔支出 → 退款**」—— 这样 iCost 会自动建立关联，
比导入能做到的还准。

---

## ⑧ 收尾

1. **抽查 3-5 笔**（尤其大额和转账）
2. **把归类错的商家加进 `config/merchant_map.json`**：

   ```json
   "海底捞": ["日常/收入", "支出", "日常餐饮", "日常三餐"]
   ```

   用得越久命中率越高，需要人工的笔数会越来越少。

3. 清空 `output/` 和 `导入文件/` 里这一轮的中间产物（或留着当存档）

---

## 频率建议

| 频率 | 适合 |
|---|---|
| **每月一次** | 推荐。账单量适中，记忆还新，一次 15 分钟能搞定 |
| 每季度 | 上限。再久就会出现"这笔是什么"的失忆账单 |

> 别攒到半年 —— 那时候补充说明框也救不了你。

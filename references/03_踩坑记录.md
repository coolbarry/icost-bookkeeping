# 03 · 踩坑记录

三个坑，每个都花了整整一轮才定位。**按严重程度排序。**

## 坑 1：把「导出格式」当成「导入格式」（第一轮）

### 症状

导入失败，但文件看起来完全没问题 —— 表头齐全、数据齐全、能正常用 Excel 打开。

### 根因

iCost 的导出文件是 **21 列**，导入模板只有 **10 列**。我一开始直接照着导出文件的列生成导入文件。

**证据就在文件名里**：iCost 导出时给你的文件叫
`（仅供查看，不用于数据恢复）iCost_20261017143331.xlsx`
—— 官方明说了这不是给你导回去用的。

| 项 | 导出（仅供查看） | 导入模板 |
|---|---|---|
| 列数 | 21 | **10** |
| sheet 名 | 收支账单 | **icost_template** |
| 日期 | `2026/09/22 01:39:50` | **`2026年09月22日 01:39:50`** |
| 金额 | 支出为负 | **全为正** |
| 账本 | 有这一列 | **没有**（导入时在 App 里选） |

10 列 = `日期 / 类型 / 金额 / 一级分类 / 二级分类 / 账户1 / 账户2 / 备注 / 货币 / 标签`

### 连带发现

**iCost 是在某个账本内部导入的**，所以一个文件只能含一个账本。
而且账本之间的一级/二级分类**完全独立**（只有 转账/还款/其他支出 跨账本共用）。
混账本的文件，分类会全部匹配失败。

### 解法

`core/export_split.py` 按账本拆分成多个文件，每个只含一个账本。

## 坑 2：xlsx 内部 XML 和官方模板不一致（第二轮）

### 症状

改成 10 列 + 拆账本之后，**仍然解析失败**。表头和数据都对，就是导不进去。

### 根因

`unzip` 开两个文件逐行对比 XML 才发现：**openpyxl 生成的 xlsx，在结构层面跟官方模板根本不是一回事**。iOS 那边的 xlsx 解析器非常挑食。

| 内部细节 | 官方模板 | openpyxl 默认产出 |
|---|---|---|
| 共享字符串 | `<si><t>日期</t></si>` | `<si><r><t>日期</t></r></si>` ← 富文本 run |
| 单元格类型 | `t="s"` + 共享索引 | 有时退化成 `t="inlineStr"` |
| 中文 | 真 UTF-8 汉字 | 有时写成 `&#26085;&#26399;` 数字实体 |
| dimension | `A1:J4` | `J4` ← 缺起点 |
| 金额 | `40` | `40.0` |

**以上任何一条都可能导致解析失败。**

### 解法

不再让 openpyxl 造文件，改为**克隆官方模板**：

```python
# core/export_split.py::write_xlsx_like_official()
src = zipfile.ZipFile(OFFICIAL_TPL)
with zipfile.ZipFile(path, 'w') as z:
    for item in src.infolist():
        if item.filename == 'xl/worksheets/sheet1.xml':
            z.writestr(item, sheet.encode('utf-8'))       # 只换这两个
        elif item.filename == 'xl/sharedStrings.xml':
            z.writestr(item, sst.xml().encode('utf-8'))
        else:
            z.writestr(item, src.read(item.filename))     # 其余原样保留
```

官方模板已存进 `config/icost_template.xlsx`，系统自己就能克隆，不依赖外部文件。

> **铁律：绝不用 `openpyxl.Workbook().save()` 直接产出导入文件。**

### 顺带的排查方法

产出两个诊断文件，用来把「文件的问题」和「导入方式的问题」分开：

| 文件 | 判断什么 |
|---|---|
| `00_诊断_官方原版模板.xlsx` | App 自带模板，**一字未改**。连它都失败 → 问题在导入方式，改文件没用 |
| `00_诊断_单笔探针.xlsx` | 只有 1 笔真实记录。失败 → 是某个字段值不兼容，继续二分排查 |

## 坑 3：导入不认「退款入账 / 报销入账」（第三轮）

### 症状

前两个坑都修完，格式彻底对了，但**退款和报销的记录还是识别不了**。

### 根因

打开官方模板看示例行，答案就在那里 —— **只有三种类型**：

```
支出 | 40   | 餐饮 | 三餐 | 支付宝
收入 | 1000 | 工资 |      | 工资卡
转账 | 1000 | 其他 |      | 工资卡 | 储蓄卡
```

`退款入账 / 报销入账 / 待报销 / 已报销` 是 **App 内部才能创建**的类型
（比如长按某笔支出 → 退款），导入解析器根本不认。

### 为什么不能退而求其次导成「收入」

从 3,582 笔历史里实测出的机制：

- `待报销(12) → 已报销(9)`：同一笔支出**改状态**，不新建记录
- `报销入账(9)`：与 `已报销` 的金额 **100% 一一对应**
  （28.13 / 36.3 / 40 / 44.03 / 49.62 / 70 / 100 / 103.16 / 490），分类也一致
- `退款入账(66)`：带**原订单的分类**冲减，**没有一笔落在「其他」上**

也就是说退款/报销本质是**冲减**，不是收入。导成收入会：

- 虚增收入（本次 3,285 元）
- 支出不会被冲回
- **储蓄率和分类口径双重失真 —— 比不记还糟**

### 解法

冲减类**不进导入文件**，改走 App 内手工补录，自动生成 `手工补录清单.md`：

- 逐笔给出 账本 / 类型 / 金额 / 分类 / 账户 / 备注
- 每笔给出**具体点击路径**
- 最优路径是「长按原订单 → 退款」，iCost 会**自动建立关联**

开关在 `config/import_fix.json`：

```json
"_导入选项": { "冲减类型可导入": false }
```

将来 iCost 支持了，改成 `true` 即可恢复写进导入文件的行为。

### 三条铁律（写备注时照着做）

1. **类型是冲减不是收入**
2. **分类沿用原订单**（不要图省事填「其他/退款」）
3. **账本必须和原订单一致** —— 跨账本冲不掉

## 其他小坑

| 坑 | 说明 |
|---|---|
| 空单元格 | 导出时 openpyxl 会返回 `None`。导入文件里**必须写成空字符串** |
| 转账/还款缺账户2 | 转出转入必须成对，缺一个就失败或产生脏数据 |
| 收入行缺账户1 | AA 收款、报销这类最容易漏 |
| 已归档分类 | 「购物」这类历史有 268 笔但 App 里已归档 → 导入匹配不到，需在 `cat_map` 重映射 |
| 组合支付 | `建行(0001)&红包&立减` → 取第一个**真实账户**，立减券不是账户 |
| 确认页输入丢失 | 备注框 `oninput` 触发全量 render 会丢输入 → 只改 state 不重渲染 |
| 确认页结果看不见 | 结果框被 72 笔记录挤到屏幕外 → 改成固定底部弹窗 |
| Python 写 JS 字符串 | `\n` 被写成真换行会搞崩整个 script → 用 `String.fromCharCode(10)` |

---

## 通用排查心法

1. **找权威基准，别猜。** 这次三次突破，全靠拿到 App 自己导出的官方模板做对照
2. **先证明"官方的东西能不能用"**，再怀疑自己的文件
3. **二分法**：官方原版 → 单笔 → 单类型 → 全量
4. **失败信息"解析失败"往往意味着结构问题，不是数据问题**
